# AutoJs Easy — 易用版功能设计方案

> 版本 v2.0 | 日期 2026-10-22 | 基于 autoengine v1.0 改进
> 核心理念：**让不会写代码的人也能用，让会写代码的人更高效**

---

## 0. 设计动机：现有版本 10 大痛点

| # | 痛点 | 影响 | 改进方向 |
|---|------|------|----------|
| 1 | 必须会 JavaScript 才能用 | 90% 目标用户被挡在门外 | 可视化编程 + 录制回放 + AI 助手 |
| 2 | 权限配置要跳 3 个系统设置页 | 首次使用流失率高 | 一键引导向导 |
| 3 | 写选择器是「盲写」——不知道屏幕上有什么 | `auto.text("登录")` 凭赌博 | 元素拾取器（悬浮窗点选） |
| 4 | 没有录制功能，每个点击都要手写 | 效率极低 | 操作录制器 |
| 5 | 报错信息是技术性的，用户看不懂 | `RhinoException at line 12` | 智能错误翻译 + 自动修复建议 |
| 6 | 没有常用任务模板 | 签到/刷视频/抢券全要从零写 | 模板库 + 一键套用 |
| 7 | 调试只能看日志，看不到执行到哪一步 | 排错靠猜 | 可视化步骤调试器 |
| 8 | API 文档和编辑器分离 | 写代码时要反复切屏查文档 | 内联 API 提示 + 悬浮文档 |
| 9 | 打包步骤太多 | 非技术用户无法独立打包 | 一键打包 + 预设方案 |
| 10 | 没有社区和分享 | 脚本无法复用 | 脚本市场 + 一键导入 |

## 2. 核心功能详细设计

### 2.1 可视化积木编辑器（P0 — 最高优先级）

**目标**：不会写代码的用户通过拖拽积木完成自动化脚本。

**设计**：

```
┌─────────────────────────────────────────────┐
│  积木工具栏          │  积木画布（拖拽区）    │
│ ┌─────────────────┐ │ ┌──────────────────┐  │
│ │ 📱 应用操作      │ │ │ ▶ 启动 微信      │  │
│ │  · 启动应用      │ │ │ ▶ 等待 「我」    │  │
│ │  · 等待控件      │ │ │ ▶ 点击 「我」    │  │
│ │  · 点击控件      │ │ │ ▶ 等待 2秒       │  │
│ │  · 输入文字      │ │ │ ▶ 截图           │  │
│ │  · 滑动屏幕      │ │ │ ▶ 找图 签到按钮  │  │
│ │ 🔍 视觉操作      │ │ │ ▶ 如果 找到      │  │
│ │  · 截图          │ │ │ │   ▶ 点击 坐标  │  │
│ │  · 找图          │ │ │ ▶ 否则           │  │
│ │  · 找色          │ │ │ │   ▶ 日志 未找到│  │
│ │  · OCR           │ │ └──────────────────┘  │
│ │ ⏰ 流程控制      │ │                        │
│ │  · 等待          │ │  [积木] ↔ [代码] 切换  │
│ │  · 循环          │ │                        │
│ │  · 条件判断      │ │                        │
│ │ 📦 数据操作      │ │                        │
│ │  · 读写文件      │ │                        │
│ │  · HTTP 请求     │ │                        │
│ │  · 存储          │ │                        │
│ └─────────────────┘ │                        │
└─────────────────────────────────────────────┘
```

**积木类别与块定义**：

| 类别 | 积木块 | 参数 | 生成代码 |
|------|--------|------|----------|
| 应用 | 启动应用 | 应用名（下拉选择已安装应用） | `app.launch("com.tencent.mm")` |
| 应用 | 等待控件 | 选择器（从拾取器导入） | `auto.text("登录").waitFor(5000)` |
| 应用 | 点击控件 | 选择器 | `auto.text("登录").findOne().click()` |
| 应用 | 输入文字 | 选择器 + 文本 | `auto.clazz("EditText").findOne().setText("hello")` |
| 应用 | 滑动 | 方向 + 距离 | `auto.swipe(x1,y1,x2,y2,500)` |
| 应用 | 长按 | 选择器 | `selector.findOne().longClick()` |
| 视觉 | 截图 | — | `images.captureScreen()` |
| 视觉 | 找图 | 模板图片 + 区域 + 阈值 | `images.findImage(img, tpl, {threshold:0.8})` |
| 视觉 | 找色 | 颜色 + 区域 | `images.findColor(img, color, {region})` |
| 视觉 | OCR | 区域 | `ocr.recognize(img, {region})` |
| 流程 | 等待 | 毫秒 | `sleep(1000)` |
| 流程 | 循环 | 次数/条件 | `for (let i=0; i<N; i++) {}` |
| 流程 | 条件 | 条件表达式 | `if (condition) {} else {}` |
| 流程 | Try-Catch | — | `try {} catch(e) {}` |
| 数据 | HTTP 请求 | URL + 方法 + 参数 | `http.get(url)` |
| 数据 | 读写文件 | 路径 + 内容 | `files.read(path)` |
| 数据 | 存储 | 命名空间 + 键值 | `storages.create("ns").put("k","v")` |
| 数据 | 日志 | 级别 + 消息 | `log("message")` |

**双向转换引擎**：
- 积木 → 代码：遍历积木树，按块类型生成对应 JS 代码
- 代码 → 积木：解析 AST（Rhino Parser），映射回积木块
- 混合模式：不支持积木的代码段以「原始代码块」积木显示

**技术方案**：
- 新增 `lib-blocks` 模块
- 积木定义 JSON Schema（可扩展）
- `BlockToCodeConverter`：积木树 → JS 代码
- `CodeToBlockConverter`：JS AST → 积木树（基于 Rhino Parser）
- UI：RecyclerView 拖拽 + ItemTouchHelper

### 2.2 操作录制器（P0 — 核心差异化）

**目标**：用户在手机上正常操作，系统自动录制每一步并生成可回放脚本。

**录制流程**：

```
用户点击「开始录制」
  → 启动悬浮录制条（🔴 录制中 | ⏸ 暂停 | ⏹ 停止）
  → 用户正常操作手机
  → 系统捕获每个操作：
      · 点击 → 记录目标控件信息（text/id/desc/bounds）
      · 滑动 → 记录起点终点+时长
      · 输入 → 记录目标控件+输入内容
      · 返回键 → 记录按键事件
      · 应用切换 → 记录 launch
  → 用户点击「停止录制」
  → 自动生成脚本 + 打开编辑器预览
```

**录制数据结构**：

```kotlin
data class RecordedAction(
    val type: ActionType,        // CLICK, LONG_CLICK, SWIPE, INPUT, KEY, APP_SWITCH
    val timestamp: Long,
    val targetNode: NodeSnapshot?,  // 控件快照（点击/输入时）
    val coordinates: Pair<Int, Int>?, // 坐标（手势时）
    val text: String?,          // 输入文本
    val duration: Long?,        // 滑动时长
    val packageName: String?    // 应用切换
)

enum class ActionType {
    CLICK, LONG_CLICK, SWIPE, INPUT, KEY, APP_SWITCH, SCROLL
}
```

**生成脚本策略**：
- 点击 → 优先用 `auto.text("xxx").findOne().click()`，降级用 `auto.click(x, y)`
- 滑动 → `auto.swipe(x1, y1, x2, y2, duration)`
- 输入 → `auto.clazz("EditText").findOne().setText("xxx")`
- 应用切换 → `app.launch("packageName")`
- 自动插入 `sleep()` 保持操作间隔
- 自动添加 `"auto";` 头部和 `auto.waitFor()`

**技术方案**：
- 新增 `lib-recorder` 模块
- `ActionRecorder`：监听 AccessibilityEvent + dispatchGesture 回调
- `RecordingToScriptConverter`：录制动作列表 → JS 脚本
- 录制悬浮条：`lib-floaty` 实现
- 录制数据可导出为 JSON，支持编辑后重新生成脚本

### 2.3 元素拾取器（P0 — 消除「盲写选择器」）

**目标**：用户在编写脚本时，直接在屏幕上点选目标控件，自动生成选择器代码。

**交互流程**：

```
用户在编辑器中需要选择一个控件
  → 点击「拾取元素」按钮
  → 开启半透明悬浮层覆盖全屏
  → 用户触摸屏幕任意位置
  → 系统高亮该位置的可点击控件（蓝色边框 + 信息卡片）
     ┌──────────────────────┐
     │ 🔵 text: "登录"       │
     │    id: btn_login      │
     │    class: Button      │
     │    bounds: [100,200,200,260] │
     │    [使用此元素] [查看子元素] │
     └──────────────────────┘
  → 用户点击「使用此元素」
  → 自动插入选择器代码到编辑器
  → 可选择匹配方式：text / id / desc / 坐标
```

**元素树浏览器**：

```
┌──────────────────────────────────┐
│ 📱 当前窗口: com.tencent.mm     │
├──────────────────────────────────┤
│ ▼ FrameLayout                    │
│   ▼ LinearLayout                 │
│     ▼ TextView "微信"            │
│     ▼ Button "通讯录"  [可点击]  │
│     ▼ Button "发现"    [可点击]  │
│     ▼ Button "我"      [可点击]  │
│   ▼ RecyclerView                 │
│     ▼ LinearLayout [可点击]      │
│       ▼ ImageView [头像]         │
│       ▼ TextView "张三"          │
│       ▼ TextView "最后一条消息"  │
└──────────────────────────────────┘
```

**技术方案**：
- 新增 `lib-inspector` 模块
- `ElementPicker`：悬浮窗 + 触摸事件拦截 + AccessibilityNodeInfo 查找
- `ElementTreeBrowser`：RecyclerView 树形展示 + 展开/折叠
- `NodeHighlightOverlay`：Canvas 绘制高亮边框
- 与编辑器集成：拾取结果直接插入光标位置
- 复用现有 `AccessibilityEngine.getSnapshot()` 获取节点数据

### 2.4 AI 助手（P1 — 自然语言编程）

**目标**：用户用自然语言描述需求，AI 自动生成脚本。

**交互示例**：

```
用户输入：「每天早上 8 点打开微信，点击我，进入设置，
           把字体调到最大」

AI 生成：
```javascript
// 定时任务：每天 08:00
"auto";
auto.waitFor();
app.launch("com.tencent.mm");
auto.text("我").findOne(8000).click();
sleep(1000);
auto.text("设置").findOne(5000).click();
sleep(500);
auto.text("通用").findOne(3000).click();
auto.text("字体大小").findOne(3000).click();
auto.text("大").findOne(3000).click();
```

用户输入：「帮我写一个自动刷抖音的脚本，每次滑到下一个视频
           停留 5 秒，刷 100 次然后停止」

AI 生成：
```javascript
"auto";
auto.waitFor();
app.launch("com.ss.android.ugc.aweme");
sleep(3000);
for (let i = 0; i < 100; i++) {
    log("第 " + (i+1) + " 个视频");
    sleep(5000);
    auto.swipe(
        device.width / 2, device.height * 0.8,
        device.width / 2, device.height * 0.2, 500
    );
}
log("刷视频完成");
```
```

**AI 助手能力矩阵**：

| 能力 | 输入 | 输出 | 实现方式 |
|------|------|------|----------|
| 脚本生成 | 自然语言描述 | JS 脚本 | LLM API + 上下文注入 |
| 脚本解释 | JS 脚本 | 自然语言说明 | LLM API |
| 错误修复 | 错误信息 + 脚本 | 修复建议/修复后脚本 | LLM API + 错误知识库 |
| 优化建议 | JS 脚本 | 优化建议 | LLM API + 性能规则 |
| 选择器建议 | 截图 + 描述 | 选择器代码 | LLM API + 屏幕元素上下文 |

**技术方案**：
- 新增 `lib-ai` 模块
- `AiAssistant`：封装 LLM API 调用（支持 OpenAI / 本地模型）
- `ScriptGenerator`：自然语言 → 脚本（注入 API 文档 + 示例作为上下文）
- `ErrorFixer`：错误信息 → 修复建议
- 上下文注入：当前屏幕元素、已安装应用列表、API 文档摘要
- 隐私模式：敏感信息（屏幕内容）可选不上传

## 6. 与现有架构的兼容性

| 改进功能 | 复用现有模块 | 新增内容 |
|---------|-------------|---------|
| 积木编辑器 | core-runtime (ScriptRuntime) | BlockToCodeConverter |
| 操作录制 | lib-accessibility (AccessibilityEngine) | ActionRecorder |
| 元素拾取 | lib-floaty (FloatyManager) + lib-accessibility | ElementPicker |
| AI 助手 | lib-net (HttpClient) + core-api (ApiRegistry) | AiAssistant |
| 模板库 | core-runtime (ScriptSource) | TemplateEngine |
| 调试器 | core-runtime (ScriptThread) + lib-floaty | DebugOverlay |
| 引导向导 | AccessibilityUtils + FloatyManager | SetupWizard |
| 定时 UI | scheduler (TaskScheduler) | ScheduleConfigUi |
| 打包简化 | packager (ApkPackager) | PackagePresets |

**核心原则**：所有新功能建立在现有引擎之上，不修改 core-runtime 和 core-api 的接口，通过新增模块和 UI 层实现易用性改进。
